# 릴스 스타일 `kinetic` — 스타일 정의서

지금까지 릴스는 한 가지 모양만 나왔습니다. 사진을 3초씩 켄번즈로 훑고 자막을 얹는
방식입니다. 이 문서는 선택할 수 있는 두 번째 스타일 `kinetic`을 정의합니다.

---

## 1. 무엇을 참고했는가

2026년 기준 숏폼 영상 가이드에서 공통으로 나오는 원칙을 하나로 묶었습니다.

- **소리 없이 본다.** 대부분의 시청이 음소거 상태라 자막이 사실상 음성을 대신합니다.
  그래서 자막이 장식이 아니라 주인공이어야 합니다.
- **키네틱 타이포.** 서체는 고정하고, 크기와 위치와 등장 타이밍으로 움직임을 만듭니다.
  서체를 여러 개 섞으면 오히려 싸 보입니다.
- **첫 1~3초가 시청 여부를 가른다.** 훅이 편집 완성도보다 중요합니다.
- **박자.** 컷 전환과 자막 등장이 일정한 간격으로 반복되면 영상이 정돈돼 보입니다.
- **노란 강조.** 굵은 노란 글자로 한 구절만 짚는 방식이 널리 쓰입니다. 전부 노랗게
  하면 효과가 사라지므로 한 영상에 한두 곳만 씁니다.

### 지금 릴스에서 반드시 고쳐야 할 것

인스타그램은 2025년 말에 하단 오디오 표시줄과 설명 영역을 넓혔습니다. 현재 기준은
이렇습니다.

| 영역 | 가려지는 범위 (1080×1920 기준) |
|---|---|
| 상단 헤더 | 위에서 약 200px |
| 하단 설명·오디오·계정명 | 아래에서 약 400px |
| 우측 액션 버튼 열 | 오른쪽에서 약 120px |

지금 릴스는 자막을 화면 아래쪽에 놓습니다. 이 위치는 인스타그램에 올리면 설명 텍스트와
겹쳐서 읽히지 않습니다. `kinetic`은 자막 기준선을 **바닥에서 480px 위**로 올려 이
문제를 피합니다.

---

## 2. 화면 규격

- 캔버스 1080×1920, 30fps
- 안전 영역: 좌우 96px, 위 200px, 아래 400px
- 자막 기준선: 바닥에서 480px (y = 1440)
- 훅 텍스트 중심: y = 820

## 3. 구간 구조

사진 장수에 따라 길이가 정해집니다.

| 구간 | 길이 | 내용 |
|---|---|---|
| 훅 | 2.0초 (60프레임) | 대표 사진 위에 짧은 한 줄. 어절 단위로 순차 등장 |
| 본문 | 사진당 2.4초 (72프레임) | 사진 한 장에 자막 한 줄 |
| 마무리 | 2.6초 (78프레임) | 어두운 오버레이 위에 매장명과 주소 |

사진 3장이면 2.0 + 7.2 + 2.6 = **11.8초**가 됩니다.

## 4. 타이포그래피

서체는 저장소에 이미 들어 있는 `fonts/NotoSansKR-VF.ttf` 하나만 씁니다. 굵기로만
위계를 만듭니다.

| 용도 | 크기 | 굵기 | 색 |
|---|---|---|---|
| 훅 | 92px | 800 | 흰색, 강조 어절만 `#FFE14D` |
| 본문 자막 | 60px | 700 | 흰색 |
| 매장명 | 104px | 800 | 흰색 |
| 주소 | 36px | 500 | `rgba(255,255,255,0.78)` |

글자가 사진에 묻히지 않도록 두 가지를 겹칩니다.

1. 텍스트 그림자 `0 4px 28px rgba(0,0,0,0.6)`
2. 자막 영역 아래쪽에 검정 그라데이션 (높이 640px, 투명 → 0.72)

## 5. 모션 규칙

- **사진 확대.** 컷마다 1.00 → 1.09로 천천히 확대합니다. 방향은 컷마다 번갈아
  바꿉니다(왼쪽 위 기준 ↔ 오른쪽 아래 기준). 같은 방향이 반복되면 지루해집니다.
- **컷 전환.** 8프레임(0.27초) 크로스 페이드.
- **자막 등장.** 14프레임 스프링. 아래에서 18px 올라오며 나타납니다.
- **박자 어긋내기.** 자막은 컷 전환과 동시에 들어오지 않고 **6프레임 뒤에** 들어옵니다.
  정확히 겹치면 둘 다 묻히고, 살짝 어긋나면 리듬이 생깁니다.
- **마무리.** 배경이 1.06에서 1.00으로 줄고 매장명이 아래에서 올라옵니다.

## 6. 대본 형식

스타일이 요구하는 자막 구조입니다.

```json
{
  "hook": "20년 내공, 숯불향",
  "highlight": "숯불향",
  "lines": ["밑반찬은 무한 리필", "참숯에 직접 굽습니다", "단골이 증명하는 맛"],
  "closing": "안마을돼지불백"
}
```

- `hook`은 12자 안쪽. 길면 두 줄로 접히면서 훅의 힘이 빠집니다.
- `highlight`는 `hook` 안에 실제로 들어 있는 어절이어야 합니다. 그 어절만 노란색이
  됩니다.
- `lines`는 사진 장수만큼 필요합니다. 모자라면 돌려 쓰고, 남으면 버립니다.
- 각 줄은 16자 안쪽. 넘으면 두 줄로 접히면서 자막이 사진을 너무 가립니다.

대본은 `lib/reelScript.js`가 만듭니다. AI 키가 있으면 모델이 쓰고, 없으면 한 줄 소개를
쪼개서 규칙으로 만듭니다. 이 저장소의 다른 AI 기능과 같은 폴백 방식입니다.

## 7. 구현 구조

기존 `/api/reels`는 손대지 않았습니다. 새 스타일은 별도 경로로 붙어서, 문제가 생겨도
지금 작동하는 기능이 멈추지 않습니다.

```
remotion/
  index.js              Remotion 진입점
  Root.jsx              컴포지션 등록 (크기·길이 계산)
  KineticReel.jsx       전체 구성 (훅 → 본문 → 마무리)
  scenes/
    HookScene.jsx       훅 구간
    PhotoScene.jsx      사진 한 장 + 자막 한 줄
    ClosingScene.jsx    매장명 마무리
  components/
    KenBurns.jsx        사진 확대 연출
    Caption.jsx         자막 (스프링 등장 + 그림자)
    Gradient.jsx        하단 그라데이션
  theme.js              색·크기·타이밍 수치 한곳에 모음

lib/reelScript.js       대본 생성 (AI + 규칙 폴백)
routes/reelsKinetic.js  POST /api/reels-kinetic
scripts/render-kinetic.js  로컬에서 렌더해 보는 CLI
```

### 왜 Remotion인가

지금 릴스는 ffmpeg 필터를 문자열로 조립합니다. 자막 위치를 20px 옮기려면 전체 인코딩을
끝까지 돌려야 결과를 볼 수 있고, 사진 2장 기준으로 1분 50초가 걸립니다. Remotion은
영상의 각 프레임을 React 컴포넌트로 그리기 때문에 브라우저에서 타임라인을 실시간으로
보면서 고칠 수 있습니다.

`리팩토링.md`에 적힌 React·TypeScript 전환과 같은 언어라는 점도 이유입니다. 화면을
만드는 실력이 그대로 영상을 만드는 실력이 됩니다.

### 렌더 비용에 대한 정직한 메모

Remotion 렌더는 내부에서 헤드리스 크롬을 띄웁니다. 지금 Render 무료 플랜(512MB)에서는
기존 ffmpeg 방식보다 무겁습니다. 그래서 이 스타일은 다음 순서로 쓰는 것을 전제합니다.

1. 먼저 렌더링을 웹 서버에서 분리합니다(작업 큐 + 워커).
2. 워커에서 이 스타일을 돌립니다.

분리 전에는 로컬에서 `scripts/render-kinetic.js`로 품질을 확인하는 용도로 씁니다.
`/api/reels-kinetic`도 동작하지만 동시 요청을 받으면 위험합니다.

---

## 8. 확인 기준

- 자막이 인스타그램 하단 UI에 가리지 않는다(바닥 480px 위).
- 같은 사진과 같은 문구로 기존 릴스와 나란히 놓았을 때 자막이 더 잘 읽힌다.
- 한글이 깨지거나 빠진 프레임이 없다.
- 사진이 1장뿐이어도, 6장이어도 길이가 자동으로 맞는다.
